# Notes — Introduction to Quantinuum's technology (b03, s01) — Callum Macpherson

## Resumen

Talk by a Quantinuum software engineer covering the company's trapped-ion hardware
roadmap (H1, H2, Helios), the Guppy quantum programming language, the Nexus cloud
platform, and five live code demos: Bell/GHZ state preparation, Qiskit-to-Guppy
interop via pytket, a T-state/magic-state injection circuit, a Steane-code
`[[7,1,d]]` error-detection example with concrete simulation statistics, and a
MaxCut/QAOA walkthrough [~00:00]–[~60:00].

## Conceptos clave

- **Quantinuum overview** [~00:00]: global, full-stack quantum computing company
  (hardware through algorithms/theory/QEC), ~8 sites worldwide, ~700 people,
  research-focused.
- **Hardware roadmap** [~00:00]: trapped-ion modality. H1 = 20 qubits, linear
  array. H2 = 56 qubits, ring shape. Helios (latest) = 98 fully-connected
  physical qubits, arranged in a "tuning fork" shape with 8 gate zones.
  Full connectivity (any-pair two-qubit gates) contrasts with superconducting
  hardware's fixed nearest-neighbor connectivity — reduces circuit complexity
  and widens the range of implementable QEC codes.
- **Gate fidelity** [~00:00]: two-qubit gate fidelity around "three nines"
  (99.9%); this is the dominant error source, typically an order of magnitude
  worse than single-qubit gate error. H2 promotional hardware-access program
  available via application/QR code.
- **Guppy language** [~00:00]: Python-embedded DSL for quantum programming,
  marked via a `@guppy` decorator. Unlike a static circuit-list representation
  (build-then-submit), Guppy supports functions, loops, conditionals, and
  recursion, compiled down to run on real devices. Built for a "dynamic" model
  of computation: the quantum device stays in constant communication with a
  classical coprocessor, enabling dynamic qubit allocation, mid-circuit
  measurement, and real-time branching/looping — as a consequence, the number
  of qubits used by a program can vary across different runs.
- **Type safety / qubit ownership** [~00:00], [~20:00]: strict/strong typing
  (compared to Rust) tracks qubit resources at compile time — a qubit must be
  consumed (measured, discarded, or returned) before the function ends, and a
  measured (deallocated) qubit cannot be reused without reinitializing it.
  Distributed via PyPI, open source on GitHub, approaching a v1 stable release.
- **Qiskit interop** [~00:00], [~20:00]: convert a Qiskit circuit to pytket
  (Quantinuum's earlier circuit-based library) via a built-in conversion
  function, then load it into Guppy with `guppy.load(circuit)` to reuse it as a
  subroutine. PennyLane interop is comparatively unsupported (unmaintained
  extension); suggested workaround is routing through Qiskit or OpenQASM as an
  intermediate format.
- **Selene simulator** [~00:00]: Guppy's built-in simulation framework, used
  for debugging/testing before submitting to real hardware.
- **Nexus cloud platform** [~00:00], [~20:00]: hosted JupyterHub environment
  with Guppy/Qiskit pre-installed; manages job submission/history, code and
  result sharing, and hosts simulators (Selene, H2 simulator) as well as device
  access. For the hackathon, only simulators (Selene + H2 simulator) are
  available; real hardware access is separate/promotional.
- **Demo: Bell and GHZ states** [~20:00]: `prepareBell` allocates two qubits,
  applies H then CNOT; a `check` call catches qubit-resource mistakes at
  compile time. Simulated for 1000 shots, giving an approximately even 00/11
  split. Generalized to GHZ states over n qubits via a for-loop of chained
  CNOTs, with the function made generic over a type variable `n`.
- **Demo: T-state / magic-state injection** [~20:00]: prepares the T-state via
  H followed by T (equal superposition with a π/4 relative, non-Clifford,
  phase), measures the qubit, and conditionally applies `S·X` if the outcome
  is 1, using native Python `if` syntax. Framed as a pattern that recurs in
  quantum error correction for injecting non-Clifford gates. A suggested
  exercise: prepare a GHZ state in constant depth using n−1 ancilla qubits via
  mid-circuit measurement and conditional logic.
- **Guppy ownership-rule examples** [~20:00]: three deliberate compile-time
  mistakes shown — (1) an allocated qubit left neither measured nor returned
  (fixed by returning it), (2) a Hadamard-test qubit left idling unmeasured,
  (3) applying a gate to a qubit after it has already been measured
  (deallocated), which requires reinitialization before reuse.
- **Demo: graph state / comp-time values** [~20:00]: applies H to all qubits,
  then CZ gates according to a graph's edges; demonstrates loading external
  Python data (the graph's edge list) into a Guppy program as a "comp time"
  value that shapes the generated circuit.
- **Demo: Steane code `[[7,1,d]]`** [~40:00]: notation = 7 physical qubits
  encode 1 logical qubit, with a distance parameter related to the number of
  correctable errors ⚠️(verify against transcript audio — consistently
  transcribed as "STEAM code"/"steam qubit," almost certainly a
  mis-transcription of "Steane code"; the same STEAM/Stim/Steane confusion
  pattern was independently observed and flagged in b02/s01.notes.md, which
  corroborates this reading). A Guppy `struct` (`SteamQubit`) bundles 7
  physical qubits as one logical qubit. Logical |0⟩ is prepared via Hadamards
  on indices 0, 4, 6 plus a configured sequence of CNOTs. Post-selection /
  early exit: an ancilla qubit is coupled to the 7 data qubits via extra
  two-qubit gates, then measured; if it indicates an error, the program exits
  early (shot discarded) rather than returning a possibly-corrupted logical
  qubit.
- **Steane-code simulation results** [~40:00]: depolarizing noise model
  (single- and two-qubit gate error rates, described by the speaker as "not
  very realistic"), 8 total qubits (7 data + 1 ancilla), 1000 shots → 968
  shots with no error, 23 shots where an error was detected and the shot was
  discarded (early exit), 9 shots where an error occurred but was **not**
  detected (passed through undetected).
- **Realistic noise model (audience Q&A)** [~40:00]: a participant (Mauricio)
  suggests a depolarizing rate around 0.03 for trapped ions, but notes real
  device noise is asymmetric — different rates for X vs. Z errors, and
  different rates for single- vs. two-qubit gates — rather than a uniform
  depolarizing channel.
- **Nexus/Selene simulation options** [~40:00]: noiseless state-vector
  simulation, stabilizer simulator (Clifford-only circuits, scales to much
  larger qubit counts), depolarizing-noise simulation, and Selene Plus (a more
  realistic, physics-informed noise model calibrated to the real Helios
  device, with configurable custom parameters). A separate matrix-product-state
  (tensor-network) simulator can simulate non-Clifford circuits and, for
  circuits with limited/local entanglement, can exceed the qubit ceiling
  (~26 qubits) of exact/state-vector simulation — it is bounded by bond
  dimension / entanglement connectivity rather than by qubit count directly.
- **Qubit capacity and reuse** [~40:00]: Helios allows at most 98 qubits in
  use at any single point in a computation; the type system prevents leaking
  unused/unconsumed qubits. Qubits can be manually reset and reused across
  different parts of a computation, but this reuse must be managed explicitly
  by the programmer (no automatic swapping/overallocation).
- **Demo: MaxCut / QAOA** [~60:00]: MaxCut = partition a graph's nodes into two
  sets maximizing the number of edges crossing between sets. Cost is defined
  over ±1 node labels; mapped to a **cost Hamiltonian** using Pauli-Z operators
  (encoding graph connectivity) and a **mixer Hamiltonian** using Pauli-X on
  every qubit (to explore the solution space beyond pure Z-rotations). In
  Guppy, the cost/mixer layers are implemented as alternating parameterized
  two-qubit gates (Z basis) and single-qubit gates (X basis), parameterized by
  angles (gammas, betas) that a classical variational loop optimizes to
  maximize the Hamiltonian's expectation value.
- **QAOA worked example** [~60:00]: a small graph is solved for 2000 shots;
  100 iterations of the variational loop find near-optimal gamma/beta
  parameters; the resulting shot distribution's two most frequent outcomes
  are bit-inverses of each other and correspond exactly to the two equivalent
  optimal graph colorings (verified by hand, since the example graph is small
  enough to solve manually).
- **Closing** [~60:00]: speaker offers to publish a GitHub repo with slides and
  demo notebooks; will be available in person (with colleague Agustín) during
  the hackathon for follow-up questions.

## Fórmulas y definiciones

- Bell state: (|00⟩ + |11⟩)/√2, prepared via H then CNOT [~20:00].
- GHZ state: n-fold generalization of the Bell-state construction (H + chain
  of CNOTs) [~20:00].
- T-state: equal superposition of |0⟩ and |1⟩ with a π/4 relative (non-Clifford)
  phase, prepared via H then T [~20:00].
- MaxCut cost function: sum over graph edges of `(1 − sᵢ·sⱼ)`, with node labels
  `sᵢ ∈ {+1, −1}` [~60:00].
- QAOA Hamiltonians: cost Hamiltonian built from Pauli-Z terms encoding graph
  connectivity (plus an identity term); mixer Hamiltonian = sum of Pauli-X on
  every qubit [~60:00].
- Code parameters `[[n, k, d]]`: Steane code = `[[7, 1, d]]` — 7 physical
  qubits, 1 logical qubit, distance `d` (not specified numerically in the
  talk) [~40:00].
- Steane-code simulation statistics (1000 shots, depolarizing noise): 968 no
  error / 23 detected-and-discarded / 9 undetected error [~40:00].

## Glosario

- **Guppy**: Quantinuum's Python-embedded quantum programming language,
  designed for dynamic, fault-tolerance-oriented programs with strict qubit
  ownership typing.
- **Nexus**: Quantinuum's cloud platform — hosted JupyterHub, job management,
  and access to simulators and real hardware.
- **Selene**: Guppy's built-in simulator; also available in a cloud-hosted
  "Selene Plus" variant on Nexus with a physics-informed noise model matching
  real Helios hardware.
- **pytket**: Quantinuum's earlier circuit-based quantum computing library,
  used as an intermediate format to import Qiskit circuits into Guppy.
- **Helios / H1 / H2**: Quantinuum's trapped-ion hardware generations (98,
  20, and 56 qubits respectively).
- **Ancilla qubit**: auxiliary qubit used to detect errors without directly
  measuring the data qubits it is coupled to.
- **Early exit / post-selection**: discarding a shot mid-program when an
  ancilla measurement indicates an error occurred.
- **Steane code**: `[[7,1,d]]` stabilizer code encoding 1 logical qubit into
  7 physical qubits (see mis-transcription note above).
- **GHZ state**: n-qubit generalization of the Bell state — equal
  superposition of all-|0⟩ and all-|1⟩.
- **QAOA (Quantum Approximate Optimization Algorithm)**: variational algorithm
  alternating cost and mixer Hamiltonian evolutions to approximate solutions
  to combinatorial optimization problems like MaxCut.
- **Matrix product state (MPS) / tensor-network simulator**: classical
  simulation method whose scaling depends on circuit entanglement structure
  rather than qubit count directly, allowing it to exceed exact-simulation
  qubit limits for low-entanglement circuits.
- **Stabilizer simulator**: classical simulation method restricted to Clifford
  circuits, capable of simulating much larger qubit counts than state-vector
  simulation.
- **Comp-time value**: external (Python-side) data loaded into a Guppy program
  at compile time to parameterize the generated circuit (e.g., a graph's edge
  list).
