# Notes — Class 09

## Resumen

Opening session of QCobalt (the hackathon-relevant final module), switching the implementation library to D-Wave's Ocean SDK. Introduces combinatorial optimization framing (MaxCut, TSP, SAT as NP-complete exemplars; SAT as the universal reduction target), then builds up the QUBO (Quadratic Unconstrained Binary Optimization) formulation from scratch: objective function as xᵀQx, worked matrix-construction examples, re-deriving MaxCut as a QUBO via an edge-check arithmetic function, the penalty-method for encoding constraints (equality/inequality templates), integer-to-binary conversion with bit-minimizing encoding (including the slack variable for inequalities), a fully worked toy example, and finally a complete (if rushed, live Q&A-heavy) PUBO formulation of the Traveling Salesman Problem (TSP) including its O(n²) variable count, two "exactly-once" constraints, cost function, cycle wraparound convention, and the missing-edge-weight trick.

## Conceptos clave

- **Course/module transition** [~00:00]: QCobalt begins today — the hackathon-focused final module, using D-Wave's Ocean SDK (the third distinct quantum library used across the workshop, after Qiskit and Google's library). Mentioned aside: a follow-on OQI-run training program (separate from this 10-day workshop) will help fine-tune hackathon problem/topic selection — announced via Discord.
- **NISQ-era optimization framing** [~00:00]: QCobalt targets NP-complete combinatorial optimization problems on NISQ hardware. Explicit caveat repeated from earlier sessions: quantum computers are not expected to solve NP-complete problems in polynomial time in general; the hackathon goal is to find *subclasses* where quantum approaches might show an advantage. Key methodological warning: fair comparison requires benchmarking a NISQ algorithm (tuned for a subclass) against a classical algorithm *also* tuned for that same subclass — not against generic classical brute force.
- **Combinatorial optimization — problem menu** [~00:00]: MaxCut (from c08); TSP (Traveling Salesman Problem — directed, weighted, complete graph; find minimum-weight Hamiltonian cycle visiting every vertex exactly once); SAT (Boolean satisfiability — is there a variable assignment making a given formula true) explicitly named as the canonical NP-complete problem to which all other NP-complete problems can be reduced (used as the standard hardness-proof technique via reduction).
- **Optimization problem taxonomy** [~00:00]: general form = optimize f(x) subject to Ax≤b. If f is linear → linear programming (solvable in polynomial time, well-established). If additionally A is positive semi-definite (all eigenvalues ≥0) → convex/SDP-type programs (efficiently solvable in general). Combinatorial optimization problems generally do *not* have this convex structure, which is why they're hard.
- **QUBO definition** [~00:00]: Quadratic Unconstrained Binary Optimization — developed partly to match D-Wave's Ocean SDK. Given an n×n matrix Q (represented upper-triangular for convenience) and a binary vector x∈{0,1}ⁿ, the objective is f(x)=xᵀQx = Σᵢⱼ Qᵢⱼxᵢxⱼ. Using xᵢ²=xᵢ (since xᵢ∈{0,1}), this splits into a linear term (diagonal entries Qᵢᵢxᵢ) and a quadratic term (off-diagonal Qᵢⱼxᵢxⱼ for i<j, given the upper-triangular convention) — the quadratic term being where the "Q" in QUBO comes from. No constraints exist by definition in bare QUBO (constraints are added afterward via the penalty method). QUBO is by default a *minimization* problem; any maximization problem is trivially converted via max f(x) = min(−f(x)) — flagged as a broadly reusable trick appearing throughout the session.
- **Worked example — building a Q matrix** [~00:00–20:00]: from a given objective function with linear terms (diagonal entries) and quadratic cross-terms (off-diagonal entries, matched to variable-pair position), the instructor builds a 4×4 upper-triangular Q matrix by reading off coefficients directly — no entries beyond quadratic (no cubic terms) allowed in bare QUBO form. A live correction occurs mid-example (a copying typo over the number of variables, corrected with audience help).
- **MaxCut re-derived as QUBO** [~20:00]: define binary variable xᵢ per vertex i (1 if in S, 0 if in R) — same encoding as c08. The edge-check arithmetic function chosen: g(xᵢ,xⱼ) = xᵢ + xⱼ − 2xᵢxⱼ, verified to equal 1 exactly when xᵢ≠xⱼ (edge crosses the cut) and 0 otherwise — explicitly flagged as *one possible choice*, not unique, chosen because it stays within QUBO's linear+quadratic form (avoids needing an absolute-value function, which QUBO can't directly express). MaxCut objective: maximize Σ_{(i,j)∈E} (xᵢ+xⱼ−2xᵢxⱼ), converted to minimization by negating: minimize Σ_{(i,j)∈E} (−xᵢ−xⱼ+2xᵢxⱼ). Fully expanded and matrixized for the running example graph (worked entries: diagonal −2,−2,−3,−3,−2 and specific off-diagonal 2's).
- **Penalty method for constraints** [~20:00–40:00]: general form: minimize f(x) + Σᵢ Pᵢ·gᵢ(x), where gᵢ is the *penalty function* for constraint i (not the constraint itself) and Pᵢ is the penalty coefficient. Required property: gᵢ(x)=0 when constraint i is satisfied, gᵢ(x)>0 otherwise. Choice of Pᵢ is problem-dependent — must be large enough to disincentivize violating the constraint, but not so large that it overwhelms the actual objective (a "Goldilocks" tradeoff, echoing c08's terminology), typically tuned empirically via the notebooks.
- **Standard penalty templates given** [~20:00–40:00] (for binary x,y): x+y≤1 → g=xy; x+y≥1 → g=1−x−y+xy; x+y=1 → g=1−x−y+2xy; x≤y → g=x−xy; x=y → g=x+y−2xy. All verifiable by direct substitution of the four binary cases.
- **General linear-equality constraint penalty (integer variables)** [~20:00–40:00]: for constraints Σᵢ aᵢyᵢ=b (integer yᵢ), penalty term = P·(Σᵢ aᵢyᵢ − b)². The square is needed because the bracketed quantity can be negative or positive when the constraint is violated — squaring makes any violation contribute positively regardless of direction.
- **Linear-inequality constraint via slack variable** [~40:00]: for Σᵢ aᵢyᵢ≤b, introduce a slack variable η (representing the "gap") to convert to equality: Σᵢ aᵢyᵢ+η=b, then apply the same squared-penalty template: P·(Σᵢ aᵢyᵢ+η−b)². For ≥ constraints, first negate both sides to convert to the ≤ standard form before adding the slack variable.
- **Integer-to-binary conversion — the naive approach and why it's improved** [~40:00]: naively, converting an integer to binary via its standard bit representation works, but wastes qubits/bits if the variable's actual range [y_lower, y_upper] is much narrower than its raw magnitude would suggest. Since each binary variable will map to a physical qubit on quantum hardware, minimizing bit count matters for memory/qubit budget.
- **Bit-minimizing integer encoding formula** [~40:00–60:00]: for yᵢ ∈ [y_lower, y_upper], let N = ⌈log₂(y_upper−y_lower+1)⌉ (bits needed for the count of distinct possible values). Representation: yᵢ = y_lower + Σ_{j=0}^{N−2} 2ʲxⱼᵢ + (y_upper−y_lower−(2^{N−1}−1))·x_{N−1,i} — i.e., all bits except the most significant use standard binary weighting, but the most-significant bit's coefficient is adjusted to (upper−lower) minus what the remaining bits can already cover, preventing the representation from exceeding y_upper when the MSB is set to 1.
- **Worked numeric example of the encoding** [~60:00]: y_lower=50, y_upper=100, target value 82. N=⌈log₂(51)⌉=6 bits. Without the MSB, 5 bits can represent up to 31 (so 50+31=81 max); the MSB's special coefficient = (100−50)−31=19, giving 50+19=69 with only the MSB set; remaining 82−69=13 represented by the standard 4-bit binary 1101 in the lower bits. Full worked bit-by-bit reconciliation confirms the formula reproduces 82 without ever allowing a value above 100.
- **Applying the same encoding to the slack variable η** [~60:00]: η's own [lower,upper] bounds are derived from the constraint structure itself: η_lower=0 (no slack needed when constraint exactly met), η_upper = b − Σᵢ min(aᵢ·y_lower,ᵢ, aᵢ·y_upper,ᵢ) — then η is converted to binary using the identical bit-minimizing formula.
- **Why integers must convert to binary at all** [~60:00]: QUBO's defining constraint is that all variables be binary — this is a structural requirement carried through to the underlying D-Wave solvers used in upcoming sessions, hence the conversion machinery, even though in practice solver libraries usually automate this conversion.
- **Fully worked toy example (constrained integer QUBO)** [~60:00–80:00]: f(y1,y2) with constraints 0≤y1≤8, 0≤y2≤5, y1+y2≥10. Steps demonstrated live: (1) convert ≥ to ≤ by negation, add slack η, get penalty (−y1−y2+η+10)²; (2) compute η's bounds (η∈[0,3] in this example, derived via the min-based formula); (3) compute N for y1 (=4 bits), y2 (=3 bits), η (=2 bits) using the log₂ formula; (4) write out each variable's bit-minimized binary expansion explicitly; (5) substitute all three expansions back into the penalty expression to get the final all-binary QUBO objective — described as fully "plug and play" once the conversion machinery is understood, though normally automated by solver libraries in practice.
- **Traveling Salesman Problem (TSP) — setup** [~80:00–100:00]: input is a directed, weighted, complete graph (missing edges handled by adding them with very large weight so they're never chosen — even weight-summing all other edges as a safe upper bound is suggested); undirected graphs are the special case wᵢⱼ=wⱼᵢ. Goal: shortest cycle visiting every vertex exactly once and returning to start — critically, the starting vertex is *not* given as input, it's part of what the solution determines.
- **Aside: best known algorithms for TSP** [~80:00]: classical brute force is 2ⁿ; the best known quantum algorithm for TSP achieves O(1.78ⁿ) — but the instructor stresses this speedup comes from classical dynamic programming (decomposing into subproblems) combined with Grover's algorithm for a quadratic sub-improvement, NOT from any NISQ/QUBO-style approach — explicitly used as a cautionary example that "NISQ approaches should be taken with a grain of salt" absent a genuinely insightful problem-specific construction.
- **TSP variable count and meaning** [~80:00–100:00]: n² binary variables xᵢₜ, where xᵢₜ=1 iff vertex i is visited at time-step t (0 otherwise); i,t both range over 0..n−1. The "time" variable encodes visitation order, not physical time.
- **TSP constraint 1 — each vertex visited exactly once**: Σₜ xᵢₜ = 1 for all i (n constraints); penalty = P·Σᵢ(1 − Σₜxᵢₜ)².
- **TSP constraint 2 — exactly one vertex visited at each time step**: Σᵢ xᵢₜ = 1 for all t (structurally symmetric to constraint 1, summed over the other index); penalty template analogous, left as an exercise by the instructor.
- **TSP cost function**: Σ_{i≠j} wᵢⱼ · xᵢₜ · xⱼ,ₜ₊₁ summed over all valid t, with the cyclic wraparound convention xᵢ,ₙ ≡ xᵢ,₀ (enforcing that the end vertex equals the start vertex, i.e. a genuine cycle).
- **Penalty coefficient choice for TSP**: P must be strictly greater than the maximum edge weight in the graph — otherwise the optimizer could "trade off" violating a visit-constraint against taking a cheap-but-invalid edge (a "race condition" between constraint satisfaction and cost minimization); this directly justifies and generalizes the earlier missing-edge trick (assign missing edges a weight larger than any real edge, or even larger than the sum of all edges, to guarantee they're never selected).

## Fórmulas y definiciones

- **QUBO objective**: f(x) = xᵀQx = Σᵢⱼ Qᵢⱼxᵢxⱼ = Σᵢ Qᵢᵢxᵢ (linear, using xᵢ²=xᵢ) + Σ_{i<j} Qᵢⱼxᵢxⱼ (quadratic). [~00:00]
- **Max→min conversion**: max f(x) = min(−f(x)). [~00:00]
- **MaxCut edge-check function**: g(xᵢ,xⱼ) = xᵢ+xⱼ−2xᵢxⱼ (=1 iff xᵢ≠xⱼ). [~20:00]
- **MaxCut QUBO (minimization form)**: minimize Σ_{(i,j)∈E} (−xᵢ−xⱼ+2xᵢxⱼ). [~20:00]
- **Generic penalty formulation**: minimize f(x) + Σᵢ Pᵢgᵢ(x), gᵢ(x)=0 iff constraint i satisfied, else >0. [~20:00]
- **Penalty templates** (binary x,y): x+y≤1→xy; x+y≥1→1−x−y+xy; x+y=1→1−x−y+2xy; x≤y→x−xy; x=y→x+y−2xy. [~20:00–40:00]
- **Linear equality penalty (integers)**: P·(Σᵢaᵢyᵢ−b)². [~20:00–40:00]
- **Linear inequality penalty (via slack η)**: P·(Σᵢaᵢyᵢ+η−b)², from Σᵢaᵢyᵢ≤b. [~40:00]
- **Bit count for integer range**: N = ⌈log₂(y_upper−y_lower+1)⌉. [~40:00–60:00]
- **Bit-minimized integer encoding**: yᵢ = y_lower + Σ_{j=0}^{N−2}2ʲxⱼᵢ + (y_upper−y_lower−(2^{N−1}−1))x_{N−1,i}. [~40:00–60:00]
- **Slack variable bounds**: η_lower=0; η_upper = b − Σᵢ min(aᵢy_lower,ᵢ, aᵢy_upper,ᵢ). [~60:00]
- **TSP variables**: xᵢₜ∈{0,1}, i,t∈{0,...,n−1}; n² variables total. [~80:00–100:00]
- **TSP constraint 1**: Σₜ xᵢₜ=1 ∀i; penalty P·Σᵢ(1−Σₜxᵢₜ)². [~100:00]
- **TSP constraint 2**: Σᵢ xᵢₜ=1 ∀t (analogous penalty). [~100:00]
- **TSP cost**: Σ_{i≠j} wᵢⱼ·xᵢₜ·xⱼ,ₜ₊₁ (summed over t, with xᵢ,ₙ≡xᵢ,₀ wraparound). [~100:00]
- **TSP penalty coefficient bound**: P > max{wᵢⱼ : (i,j)∈E}. [~100:00]
- **Best-known TSP complexities**: classical brute force O(2ⁿ); best known quantum (dynamic programming + Grover) O(1.78ⁿ). [~80:00]

## Glosario

- **QUBO (Quadratic Unconstrained Binary Optimization)**: optimization problems expressible as xᵀQx over binary x, with no explicit constraints (constraints handled via penalties). [~00:00]
- **PUBO**: implied generalization of QUBO used loosely in the transcript when discussing TSP's formulation (Polynomial Unconstrained Binary Optimization) — not explicitly spelled out in the transcript but used interchangeably with QUBO-style formulation for TSP.
- **Penalty function / penalty coefficient**: gᵢ(x) encodes whether constraint i is violated (0 if satisfied); Pᵢ scales how costly a violation is to the objective. [~20:00]
- **Slack variable (η)**: an auxiliary variable absorbing the "gap" in an inequality constraint so it can be rewritten as an equality. [~40:00]
- **Bit-minimizing binary encoding**: an integer-to-binary conversion scheme that uses the minimum number of bits dictated by the variable's actual range, with an adjusted most-significant-bit coefficient to avoid representing out-of-range values. [~40:00–60:00]
- **Dynamic programming**: classical algorithmic technique (decomposing a problem into overlapping subproblems) used, alongside Grover's algorithm, in the best-known quantum TSP algorithm — explicitly not a NISQ-style technique. [~80:00]
- **Hamiltonian cycle**: a cycle visiting every vertex exactly once and returning to the start — the structure sought by TSP. [~80:00]
- **Missing-edge weight trick**: assigning an artificially large weight to a non-existent edge (to satisfy a "complete graph" input requirement) so that the edge is never selected in a valid solution. [~80:00–100:00]
