## Conceptos clave

- **Course logistics / module structure** [~00:00]: QBronze (introductory, now finished) → QNICL (today's optional module, bridges Bronze to Cobalt, skips historical oracle algorithms like Simon's, Bernstein-Vazirani, Deutsch-Jozsa) → QCobalt (hackathon-relevant, starts tomorrow with variational/heuristic optimization algorithms like QAOA). Today's notebooks/assessments are optional for certification but the MaxCut content itself is required knowledge since it recurs with variational algorithms later.
- **Alternate Grover interpretation — diffusion operator U** [~00:00]: recall G = H^⊗n·Z_0·H^⊗n·Z_f from c07; defining U ≡ H^⊗n·Z_0·H^⊗n (the "diffusion operator," carrying the minus sign, so G=U·Z_f) gives U = 2|H⟩⟨H| − I in matrix form (uniform-superposition outer product, scaled by 1/N, minus identity).
- **Per-amplitude update rule** [~00:00]: applying U to an arbitrary state Σ_x α_x|x⟩ updates each individual amplitude as α_x → 2μ − α_x, where μ = (1/N)Σ_x α_x is the mean amplitude — i.e., "inversion around the mean." Contrasted with yesterday's subspace-level (|A⟩/|B⟩) view: this is the same algorithm viewed one amplitude at a time.
- **Visualizing amplitude amplification** [~00:00]: starting from uniform superposition, Z_f flips the sign of the marked item x* (single-marked-item case), slightly lowering the mean μ; applying U then bumps α_x* up by roughly 2/√N per iteration (worked arithmetic: −1/√N → 3/√N → 5/√N → ...) until the numerator approaches √N, giving near-certain success — the same amplitude-amplification behavior derived geometrically in c07, now derived amplitude-by-amplitude. Confirms the same overshoot phenomenon: continuing past the optimal point starts decreasing the amplitude again, because the 1/√N approximation to μ breaks down once amplitude concentrates.
- **Circuit implementation of the diffusion operator (Z_0)** [~00:00]: claim that a 3-layer circuit — X on all qubits, multi-controlled-Z (control = all qubits, target = last qubit), X on all qubits again — exactly implements I−2|0^n⟩⟨0^n| (i.e. Z_0). Verified case-by-case: for x=0^n, all qubits flip to 1 after the first X layer, so the multi-control-Z's controls are all satisfied and its target is also 1, applying the −1 phase; the second X layer restores the state, leaving only the acquired minus sign. For any x≠0^n, at least one qubit is 0 after the first X layer, so either a control fails (Z doesn't fire) or the target is 0 (Z leaves it unchanged) — either way the net transformation is identity. Framed as a reusable trick: implementing black-box phase-flip oracles via multi-control operations.
- **Graph theory setup for MaxCut** [~20:00]: an undirected graph G=(V,E) — vertex set V={v1,...,vn}, edge set E of unordered pairs {vi,vj} — explicitly distinguished from a plotted/Cartesian "graph" (a CS/discrete-math data structure, not a chart). Complete graph = all vertex pairs connected; graphs need not be complete to be valid/connected.
- **Cut (definition)** [~20:00]: a partition of V into two non-empty sets S and R (S∪R=V, S∩R=∅). Size of a cut = number of edges crossing between S and R (NOT vertex count) — worked examples given (cut size 1, cut size 3, then a search for the max cut of size 4 and later size 5 on a running example graph).
- **MaxCut problem (optimization form)** [~20:00]: given G, find the partition (S,R) maximizing the number of crossing edges. Labeling convention: define f:V→{0,1} where f(v)=1 if v∈S ("colored"/blue), f(v)=0 if v∈R ("red") — a coloring function induced by a fixed partition.
- **Decision vs. optimization version** [~20:00]: MaxCut's natural form is optimization (not decision), but NP-completeness applies specifically to decision problems. Decision version: "does G contain a cut of size ≥ K?" (yes/no). Connection built via binary search over K (same logic as yesterday's structured-vs-unstructured search discussion): repeatedly querying "cut ≥ K?" and adjusting K up/down narrows to the optimal value with only logarithmic overhead — meaning an NP-complete decision problem implies its optimization counterpart is at least as hard, but solvable via polynomially-many (log-many) decision-problem calls.
- **MaxCut is NP-complete**; best known classical algorithms are essentially brute-force over all 2^n partitions. Grover's algorithm gives a quadratic improvement: O(2^n) → O(√(2^n)) — "not exponential-to-polynomial, but a respectable quadratic improvement." Explicit contrast drawn with NISQ-era heuristic algorithms (QAOA, VQE, etc., covered starting tomorrow in QCobalt): those lack the provable complexity guarantees that Grover-based approaches have, which is flagged as a recurring hackathon pitfall (claiming quantum advantage without being able to actually prove it).
- **Aside: min-cut/max-flow** [~20:00]: mentioned only to distinguish it from MaxCut — the min-cut/max-flow problem is known to be solvable in polynomial time classically and is not covered further.
- **Encoding**: n graph vertices ↦ n qubits; qubit state 0 = vertex in R (red), 1 = vertex in S (blue) — worked example with a 4-vertex coloring mapped to a computational basis state. [~40:00]
- **Bipartite graphs (special case)** [~40:00]: V partitions into disjoint S,R with no edges *within* either S or R (all edges cross). Worked examples distinguishing bipartite vs. non-bipartite graphs by testing candidate partitions. Pedagogical point: for bipartite graphs, MaxCut is trivial — the max cut is exactly the full edge count (all edges cross by definition), and bipartiteness itself is classically checkable in polynomial time (O(n²) mentioned) — so this special case yields **no quantum advantage claim** (classical is already efficient); it's presented purely as a simpler stepping-stone before the general (non-bipartite) construction. General hackathon lesson drawn explicitly: look for a "Goldilocks" subclass of a hard problem — one where classical algorithms are *not* known to be efficient but a discovered structure lets a quantum algorithm plausibly do better; attacking full NP-complete generality directly is usually not where an advantage is found.
- **Edge-check subroutine** [~40:00]: for an edge (x,y), an ancilla qubit E_xy is computed via two CNOTs (parity/XOR of x and y) — E_xy=1 iff x and y are colored differently (i.e., the edge legitimately crosses the cut); E_xy=0 if x,y have the same color. This is the same parity/reversible-XOR pattern used in earlier sessions.
- **Oracle construction for bipartite graphs** [~40:00]: (1) Hadamard layer on all n vertex qubits → uniform superposition over all 2^n colorings; (2) edge-check CNOTs computed for every hard-coded edge into dedicated ancilla qubits; (3) multi-controlled-NOT with all edge-check qubits as controls, flipping an answer qubit exactly when *all* edges cross (valid for bipartite graphs, where a correct 2-coloring makes every edge cross); (4) Z on the answer qubit applies the phase-kickback minus sign; (5) uncompute (apply U† to undo steps 2–3, restoring ancillas, per reversible-computation principles from c07) — leaving only the acquired phase. Net effect: this whole sequence implements Z_sub_f for MaxCut, pluggable directly into Grover's algorithm (from c07) as a black-box oracle.
- **General (non-bipartite) graphs — need for summation** [~40:00–60:00]: cannot assume all edges cross (since with an arbitrary coloring, only some edges do); must instead *count* how many edge-check qubits are 1 (i.e., compute cut size for the current coloring) and compare that count against threshold K from the decision-problem formulation. This requires: (a) a classical-style adder circuit summing the edge-check qubits into a binary "sum" register (worked example: 3 edge-check qubits require a 2-qubit sum register to hold values 0–3, with a described 3-stage adder circuit including an explicit note about handling carry/overflow); (b) a binary-comparator circuit checking whether the sum register's value ≥ K (K provided as a binary constant; comparison reduces recursively down significant bits, illustrated with example thresholds "≥4" and "≥6" mapped to concrete comparator sub-circuits).
- **Full algorithm structure (general case)** [~60:00]: the entire (Hadamard → edge-check → sum → compare-to-K → phase kickback → uncompute) sequence constitutes one implementation of Z_sub_f, which is then plugged into Grover's algorithm as before (run for O(√(2^n)) iterations). The decision-to-optimization binary search over K forms an outer tree in which *each node is itself a full run of Grover's algorithm* — giving overall runtime O(√(2^n)) per node × O(log(range of K)) nodes, i.e. Grover's quadratic speedup plus a logarithmic search overhead (the same overhead a classical decision-to-optimization reduction would also incur, so it doesn't erode the quantum advantage).
- **Multiple-solutions caveat** [~60:00]: if several colorings achieve the max cut, Grover's algorithm (per the c07 analysis with multiple marked items) returns *one* valid solution with high probability, not all of them.
- **Fragility of quantum advantage claims — Jandry's problem** [~60:00]: a few years ago Mark Jandry (per transcript, likely "Yamakawa" or similar — name uncertain) proposed a structure-free problem with an apparent proven exponential quantum advantage; the instructor notes that just last year a classical algorithm was found that matches it, "de-quantizing" the claimed advantage — reinforcing the same cautionary theme as Ewin Tang's result from c02, now framed as a live, ongoing risk for hackathon-style advantage claims.

## Fórmulas y definiciones

- **Diffusion operator**: U = H^⊗n·Z_0·H^⊗n = 2|H⟩⟨H| − I; G = U·Z_f. [~00:00]
- **Amplitude update under U**: α_x → 2μ − α_x, μ = (1/N)Σ_x α_x. [~00:00]
- **Z_0 circuit**: X^⊗n → multi-controlled-Z (all qubits control, last qubit target) → X^⊗n; implements I − 2|0^n⟩⟨0^n|. [~00:00]
- **Graph**: G=(V,E), V={v1,...,vn}, E ⊆ unordered pairs of V. [~20:00]
- **Cut**: partition V=S∪R, S∩R=∅, S,R non-empty; size(cut) = number of edges with one endpoint in S and one in R. [~20:00]
- **MaxCut (optimization)**: maximize size(cut) over all partitions (S,R). [~20:00]
- **MaxCut (decision)**: does G have a cut of size ≥ K? [~20:00]
- **Coloring function**: f:V→{0,1}, f(v)=1 if v∈S, f(v)=0 if v∈R. [~20:00]
- **Bipartite graph**: ∃ partition S,R of V with no edges within S or within R (all edges cross). For bipartite graphs, max cut size = |E| (total edge count). [~40:00]
- **Edge-check**: E_xy = x⊕y (via two CNOTs) — 1 iff x,y differently colored. [~40:00]
- **Runtime**: classical brute force O(2^n) → Grover-based O(√(2^n)) per decision query, × O(log(range)) queries for the full optimization search via binary search over K. [~20:00–60:00]

## Glosario

- **Diffusion operator (U)**: the H^⊗n·Z_0·H^⊗n component of Grover's operator G, interpretable as "inversion around the mean." [~00:00]
- **Undirected graph, vertex, edge**: standard discrete-math/CS graph data structure — explicitly not a Cartesian plot. [~20:00]
- **Cut, cut size, MaxCut**: see Fórmulas y definiciones. [~20:00]
- **Bipartite graph**: a graph whose vertices split into two sets with no intra-set edges. [~40:00]
- **Edge-check qubit**: ancilla qubit computing the XOR/parity of two vertex qubits, indicating whether the corresponding edge crosses the current cut. [~40:00]
- **Adder/comparator circuit**: classical arithmetic circuits (binary addition and ≥-comparison) implemented reversibly within the oracle to compute and threshold the cut size. [~60:00]
- **De-quantization (Jandry's problem)**: a structure-free problem once believed to have exponential quantum advantage, later matched by a classical algorithm — echoes the Ewin Tang precedent from c02. [~60:00]
